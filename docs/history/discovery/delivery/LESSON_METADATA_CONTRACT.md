# Lesson metadata + feedback contract

Owner addition: “for the saved lesson build extensive meta data what model created time taken, instructions went through and device used and how many successfull learnings were given from that lesson and for success just add a thumbs up and down so user can feedback”. This extends the current Opus-tutor+archive task; no public deployment, real-child data, payment, new provider or sensing authorization follows.

## Shared API (backend and UI must implement exactly this shape)

1. `POST /api/lesson` continues existing request dialects. Optional `device` is a strict coarse descriptor `{browser, os, type}`: browser one of chrome/edge/firefox/safari/other/unknown, os one of macos/windows/linux/android/ios/other/unknown, type one of desktop/tablet/mobile/unknown. Missing => unknown; no full user-agent, IP, hardware IDs, precise screen sizes or fingerprinting. This descriptor is NOT part of the pedagogical cache key. It is reported-by-client, not authenticated hardware evidence.
2. Both fresh and cached successful responses include the existing `lesson`, `provenance`, and `library`. Extend `library` to `{saved, cached, id, recordId, metadata, feedback}`. `recordId` is a validated full64hex content/version identifier, NOT the shortened request-key ID. Feedback is per generated lesson version, not per topic/request key.
3. `metadata` has `schemaVersion:1`, `createdAt` (ISOUTC), `model:{requested,configured,reported,provider,endpointHost,reasoningRequested,reasoningObserved}`, `timing:{generationMs}`, `instructions:{system,teachingGuidance,lessonPrompt,contract,hashes,implementationVersion}`, `device:{browser,os,type,source:'client-reported'}`. All timings measured with monotonic clock; absent provider timing stays absent. Device means the request that generated the version; a later cache-hit device must not rewrite it. Preserve optional safe usage/token/stopReason data only if actually observed. Record timestamps, schema/prompt/validator/bridge hashes, lesson-content hash, dialect/age-or-grade/language/goal/adaptation context. Source for instructions is the application's teaching inputs ONLY: never this assistant's prompts, hidden reasoning, secrets, raw provider errors, nickname fields, learner answers or session contents. The free-text goal can itself be personal; keep private, don't claim anonymization.
4. `feedback` is `{thumbsUp, thumbsDown, total, reportedHelpful, semantics:'self-reported-helpfulness'}`. All nonnegative integers; `reportedHelpful === thumbsUp`. Never label these validated learning, mastery or efficacy. No auto-increment from viewing, loading, generating or answering correctly.
5. `POST /api/lesson-rating` JSON `{adultTest:true, recordId, vote:'up'|'down'|null, voterToken}` → `{ok:true, recordId, vote, feedback}`. `voterToken` is a random128-bit lowercasehex token created only for explicit feedback, scoped to the lesson version in this browser. It is not a profile/account ID. Store only a hash in a separate private feedback record. Repeating the same vote/token is idempotent; changing up→down moves the vote; null removes it. Counts survive restart and are returned on subsequent cache hits. Endpoint has same-origin checks, strict body/type/size validation, rejects unknown recordId before writes. No unauthenticated cloud exposure. This is local duplicate prevention, NOT authenticated multi-user abuse resistance.
6. `GET /api/lesson-library/<recordId>` returns `{recordId,metadata,feedback}` for a known archive record (same-origin private owner runtime only),404otherwise. No raw arbitraryfilepaths or directory listings. Makes previously saved lesson details available after UI reload when its recordId was saved locally. Do not expose voter-token hashes.

## Minimal implementation boundaries

- Backend owner: server.mjs, lesson-store.mjs, new metadata/rating tests and library docs. Reuse current atomic file store. Keep generation records immutable; feedback in separate atomic owner-only files so votes never invalidate a lesson's digest/cache key. Validate and digest metadata along with record content. No arbitrary expiry/deletion. Preserve every real version. Save-before200; file fsync failures must not be swallowed and falsely claim durable storage. Directory sync unsupported error handling must be explicit. Strict cached wire model equality must match expected model, not merely be nonempty. Preserve endpoint/request/reasoning facts from bridge in server allowlist. Existing tests/evidence unchanged; additive tests.
- UI owner: app.mjs, minimal styles if necessary, new UI tests only. Show an accessible 👍 Helpful / 👎 Not helpful pair with aria-pressed, visible saving/error state and EN/ES text. One browser/lesson vote can change/remove. No optimistic false success or count increment on request failure; ignore late responses after profile/lesson changes. Display actual counts as reported helpful/not helpful. Native <details> “Lesson details” shows model identity, creation time, generation time, source device and application instructions as text nodes. Render no untrusted HTML. Preserve browser-local data controls; only store a minimal library reference with saved work when that existing remember control permits it. Feedback tokens may persist only after explicit voting; storage failure uses in-memory fallback with honest notice. Reset profile/remember state must not be misrepresented as deleting the server library.
- Bridge owner: ai_bridge.py and new bridge safety tests only. Keep the now-observed working AIAgent native path, capture provider response model and outbound request facts, restrict canonical origin components, bound retries/number of dispatches, map errors to typed code+status without raw prose. No new live control: parent will use the actual lesson HTTP request after integration.
- Independent spec owner: new addendum and bounded verifier from these requirements BEFORE reading implementation. Frozen-snapshot checks then fresh CTO review; no production edits.
