# Release gates — K–8 Family Companion (COO draft v0.1)

**Status:** COO recommendation, 2026-10-02, not approved policy. Coordinator reconciles; gatekeepers named below hold the pass/fail call for their gate. Gates run beside the frontend build; a red gate stops that gate's claim, not delivery work. No gate may be passed on a worker report or an exit code alone.

**Gate states:** not started · in progress · evidence attached · verified (gatekeeper ran or inspected the artifact) · owner-accepted (G2, G4 only) · blocked-deferred (G4 items by design).

**Evidence directory convention:** `company/operations/<team>/evidence/<gate>-<YYYYMMDDTHHMMSSZ>/` containing `command.txt`, `exit_code.txt`, `report.*`, screenshots. Old evidence is never overwritten; `company/coordinator-evidence/**` and `evidence/**` are read-only history.

## Rules across gates

1. **Order:** G1 continuously on the candidate → G3 per slice → G2 only on spec-compliant screens → G4 in parallel as paper work, never passable by the demo.
2. **No skipping:** a gate reaches “verified” only when the named gatekeeper ran or inspected the artifact personally and wrote the row in `company/operations/delivery/STATUS.md` with label, path, date.
3. **Scope honesty:** every pass states its tested scope (“shell checks only”, “desktop Chrome only”, “EN only”). A count without scope is not a result.
4. **Deferred stays visible:** deletion, provider retention, native Spanish, real child/consent, device, assistive technology, participant access, budget/deadline are listed as open in every status summary until G4 evidence exists. The demo never closes them.
5. **Owner load:** G2 packets arrive batched with concrete screens and at most two owner-only questions; no abstract questionnaires.
6. **Red results:** preserved in place with the new evidence dir; the fix gets its own later dir. Never rewrite an old failure as a success.
