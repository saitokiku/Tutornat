## Per-criterion results

1. **Criterion 0 / cluster + harness** — PASS as corrected by the context pack (PM-owned cluster, external mode). PG 17.11 pinned in `PG_VERSION` and verified against `server_version_num` at connect. Harness opens N ≥ 4 independent backends with per-connection login + `SET ROLE`. Residue: the self-managed path (`initdb`/`pg_ctl` under `tests/engine/pg/data`) was executed by nobody — the builder discloses this in the README and my sandbox cannot run it either. It is unverified code, fail-closed (`LC_ALL` guard, version check).
2. **Schema and migrations** — PASS. Tables for attempts (frozen columns, lifecycle CHECKs), items/rubrics (versioned, approval, family, context_tag), exposure_events, evidence_events (`class`, writer-owned `qualifying`, CHECK that qualifying needs an attempt and an unassisted/retention class), projections (`certification` CHECK = 'none'). Append-only statement triggers on six tables, row trigger freezing attempt provenance and terminal states. Idempotent (`--reapply` proven), forward-only declared and `--down` refuses.
3. **Roles** — PASS. Only `assessment` may execute `issue_attempt`/`finalize_attempt`; `learner` may submit; `tutor` may record exposure and practice; `report` has no mutation entry point. All tables revoked from the four roles except SELECT; the writer is a NOLOGIN owner of fixed-search-path SECURITY DEFINER functions, subject to RLS, with no membership path. Views are `security_invoker`. Proven by executed negatives (c2, c3) and my own matrix below.
4. **Household isolation** — PASS. `e2.principals` binds `session_user` to a household; RLS on all 12 tables with FORCE; views inherit through the invoker. My matrix: 2 households × 4 roles × 15 relations, 342 checks, 342 passed (0 leaked rows, own rows > 0, UPDATE/DELETE across household → 42501). GUC (`set_config('app.household_id')`, `SET e2.household_id`), `SET ROLE` to any other role/login/owner, and `SET SESSION AUTHORIZATION` to another login all fail (42501).
5. **Barriers** — PASS. Same-attempt race: 12 of 12 concurrent pairs (opposite scores from two assessment connections) returned identical results with exactly one evidence row; later replay with a different score returns the first result; a different response → P0001. Builder's c4 additionally proves latch-before-finalize under equal timestamps with a JS latency gate, partial failure + lost-ack retry, real 40001 retry, projection serialization, revocation under serializable retry. `barriers.cjs` (`gate`, `waitBlocked`, `lockSkills`) and `harness.transaction` are importable by A and B.
6. **E1 on PostgreSQL** — PASS. 16/16 through a `pg` adapter implementing the `Queryable` surface of `lib/tutor/db/index.ts` (test-level fixture, like E1's SQLite adapter; no `lib/` change). Dialect delta documented in `E1-ADAPTER.md`.

## Residue (non-blocking; listed for A/B and the PM)

1. Add c1 assertions for wrong score, ungraded score and familiar item (mutants M4/M5).
2. `e2.item_presentations` exposes draft and rejected item `content` to learner/tutor/report within the household, and the `approval` column is not granted, so callers cannot filter. A should serve only approved items or the view should filter on approval.
3. `e2.principals` and `e2_migrations.applied` use FORCE RLS with no policy: the migration owner must be a superuser or BYPASSRLS, otherwise `e2.household_id()` returns NULL for everyone (fails closed). Worth one line in `db/README.md`.
4. Learner identity inside a household is caller-asserted (`p_learner`): any `learner` login of a household may submit for any learner of that household. The seam is household-scoped by design; A/B must bind learner identity above the SQL layer.
5. `prove.cjs` c0 hard-codes `versionNum==='170011'` instead of reading `PG_VERSION`.
6. `reproduce.cjs` uses `node -e` for the version step and extracts `docs/` from the base archive; a Claude worker sandbox cannot run it end to end. Individual steps run fine.
7. Self-managed cluster path unexecuted by anyone (disclosed by the builder).
