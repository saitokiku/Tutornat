## 5. The E2E failure on PR #60: evidence and the fix to make

The failing spec is upstream's `e2e/tests/recent-video-thumbnail.spec.ts`
(`seedVideoThumbnailStage`). It fails on CI in some runs and passed 1 of 2 locally per
test on `--repeat-each=3` (8 passed, 1 failed) against a CI-identical production build
(`TUTOR_MODE=0 NEXT_PUBLIC_TUTOR_MODE=0 NEXT_PUBLIC_MAIC_EDITOR_ENABLED=true`, port
3002). The instrumented copy of the spec and its config are in this seat's scratch
folder and are not in the repository; the findings are what matter:

1. The spec does `page.goto('/', { waitUntil: 'networkidle' })` and then
   `page.evaluate(...)` to write IndexedDB. In the failing run `networkidle` fired 7 ms
   after the last JavaScript chunk finished loading and **before hydration**: no
   `/api/server-providers`, `/api/comfyui-workflows` or `/api/access-code/status`
   request had been made yet (they come 250 ms later).
2. The evaluate opens `MAIC-Database` with `indexedDB.open(name)` and no version. With
   the app's Dexie (version 17, `lib/utils/database.ts`) not yet open, that call
   **creates an empty version 1** database. The transaction on `mediaFiles` then throws
   `NotFoundError: One of the specified object stores was not found` inside an IDB
   callback, which is uncaught (a `pageerror`, not a rejection), so the evaluate never
   settles on its own.
3. Dexie then tries to open version 17 and logs `Upgrade 'MAIC-Database' blocked by
   other connection holding version 0.1`: the test's own connection is the blocker.
4. About 1.1 s after the `pageerror`, Playwright reports `Execution context was
   destroyed, most likely because of a navigation`. The trace's network log holds
   exactly one document request for the whole test, so the page did not reload; the
   one navigation event after hydration is a same-document one that every run shows.
   The exact mechanism that tore down the context is not pinned; it did not need to be
   for the fix.

**Fix made** (small patches in the upstream spec with `// KAIZEN:` comments, per
`CLAUDE.md`). The first version only waited for `indexedDB.databases()` to list
`MAIC-Database` at version 17, and CI still failed on every attempt of the legacy-ref
test (run 36730208038). A local trace of the same failure showed why: the version is
listed **while Dexie's upgrade transaction is still running**, so the wait resolved
before the stores existed; navigating away at that moment aborted the upgrade and the
database vanished, the seed created an empty version-1 database, threw
`NotFoundError` inside an IndexedDB callback, and hung until the test timed out, at
which point Playwright reported the hang as "Execution context was destroyed". The
second version therefore waits until an `open()` of the database succeeds with the
`mediaFiles` store present (never creating it: an unexpected `upgradeneeded` aborts),
runs the seed from a same-origin static document (`/logos/openai.svg`) so no
application code runs beside it, rejects instead of hanging on a blocked or missing
database or a throw inside a callback, and names any navigation seen during the seed
in its error. Validated against the CI-identical production build with the
repository's own spec: 24 of 24 on `--repeat-each=8` with 2 workers, and the full
suite 29 of 30 (the one failure, `interactive-iframe-keepalive-619`, fails identically
on this sandbox's Chromium before and after the change and passes on CI). If CI still
fails on this spec, the error message now carries the navigations seen; a background
workflow was also investigating the flake (section 7).

## Appendix A. Whiteboard diagnosis (read-only, from code, logs and screenshots; nothing was changed)

**Headline.** The pipeline works end to end with a real model: the pre-D36 production
screenshot `docs/evidence/replan/before-session-turn-d-light.png` shows eight drawn
items, and `docs/LOG.md` records a local smoke on the real Gemini key with five
whiteboard actions in one work turn. The same screenshot shows what "not working"
looks like when it does draw: labels at about 9 px, one label over the moon, the 16:9
sheet filling only the lower half of the pane. There is **no evidence anywhere that
`openai:gpt-5.4-mini`, the live model since 2026-09-30, has ever emitted a `[[wb]]`
tag**: D40 reports "no error frames" and says nothing about `action` frames, and
production logs for session `ses_Hir8cJGiqjO3ChU4` (14:04 to 14:08 UTC, six turns) show
no truncated-tag or stream-failure lines, so whether any tag was emitted is invisible.

**Grammar and parser** (`lib/tutor/prompts/whiteboard.md` lines 7 to 15;
`lib/tutor/turn/actions.ts` lines 24 to 35, 88, 130 to 145; `lib/tutor/turn/tags.ts`):
`[[wb <one JSON object>]]` with ten types (`wb_open`, `draw_text`, `draw_latex`,
`draw_shape`, `draw_line`, `draw_table`, `stroke`, `highlight`, `clear`, `delete`); sheet
1000 by 562.5; an origin off the sheet drops the action. Tags split across stream
chunks survive (tested in `tests/tutor/turn.test.ts`). What does not survive, all
silently: `[[wb: {…}]]` (the colon makes the JSON unparsable), `[[WB …]]`,
`[[whiteboard …]]`, `[[reaction: smile]]`, single quotes, trailing commas, unquoted keys,
and single-backslash LaTeX (`\frac` becomes a form feed, `\times` a tab, `\div \sqrt
\cdot \pi` invalid JSON). A missing `}` swallows up to 4,000 characters of speech. Drops
are logged at `debug` only (`lib/tutor/turn/engine.ts` about line 380) while the default
`LOG_LEVEL` is `info`, so production never says why a tag died.

**What the prompt says.** `whiteboard.md` is loaded every turn and is vendor-agnostic,
with one-line examples and no worked full turn. It says any explaining turn carries
at least one `[[wb]]`, but the per-turn instruction only mentions drawing in the WORK
branch of `buildTurnInstructions` (`lib/tutor/prompts/build.ts`); greet, intake,
check-due, silence and wrap say nothing, and the phase machine is greet → intake →
work (`lib/tutor/session/state-machine.ts` lines 126 to 131), so the earliest drawing
is the tutor's third turn. Competing rules a small model follows instead: "at most
two sentences and then one question" (`persona.md`), the opening-sentence rule, "never
announce the drawing". Worst: the model never sees its own past tags, because the
transcript history stores `outcome.text` with tags stripped (`engine.ts` about line
466; `lib/tutor/turn/context.ts` lines 157 to 165), so from turn two its own examples
show a tutor that does not draw. On gpt-5.4-mini the call runs with `reasoningEffort:
'none'` (`lib/ai/model-metadata.ts` lines 283 to 287) and the temperature is dropped
(today's production warning: "temperature is not supported for reasoning models").

**Client path.** `action` frames are applied unconditionally
(`lib/tutor/voice/turn-controller.ts` about line 455;
`components/tutor/session/use-tutor-session.ts` lines 213 to 216); `greet()` and text
mode use the same path; the pane is visible at 390 and 1280 px. Scale is
`min(w/1000, h/562.5)` (`whiteboard-canvas.tsx` lines 410 to 413): about 0.55 at 1280 px
(18 px text renders at about 10 px) and 0.36 at 390 px (about 6 px). Quiet client
drops: a highlight whose target is not on the board, a LaTeX that fails KaTeX
(`components/tutor/board/reducer.ts` about line 165), and the SSE client's one retry
replays text only (`engine.ts` lines 170 to 181), losing that turn's actions.

**Ranked causes and smallest fixes.**

1. gpt-5.4-mini emits few or no tags (needs a live call to confirm). Run
   `npx tsx scripts/tutor-turn-smoke.ts --rate 10` with
   `MODEL_ROUTES={"tutor-live-turn":"openai:gpt-5.4-mini"}`; if under 80 % of work
   turns carry a tag, add a two-turn worked example and put "this turn must contain
   at least one `[[wb]]`" in every teaching branch.
2. Tags emitted but malformed and dropped silently (needs a live call). Promote the
   drop log to `warn`; tolerate `[[wb: ` in `splitTag`.
3. Draws but unreadable (confirmed from code and screenshot). Clamp the font-size
   floor to about 28 in `actions.ts` about line 150; let the sheet fill the pane.
4. Nothing before the third turn (confirmed from code). Allow a drawing in intake when
   the learner names a problem.
5. Replay after a dropped stream loses actions (confirmed, rare). Replay `state.board`
   deltas in `replayTurn`.

**Distance from "draws well".** The ops are primitives only: no number line, fraction
bar, area model, graph, step list or word underline as first-class verbs, so each must
be composed from 5 to 15 primitive tags in one turn, which a small model will not do
reliably. The SSE contract already treats `action` frames as independent of speech
(`lib/tutor/turn/README.md`; the client applies them in arrival order; board state is
server-side `state.board`), so a second, stronger drawing model can be added inside
the engine without a new channel: feed it each sealed sentence plus "board now" and
yield its validated actions into the same stream, off the first-audio path. Upstream's
separate `scene-actions` stage (`lib/server/model-routes.ts` line 138,
`app/api/generate/scene-actions/route.ts`) is the precedent. Drawing will lag speech by
one sentence unless the drawing model is warmed on the learner's text.
