# Research: Scale and cost (2026-09-30)

Produced by a research agent on 2026-09-30 for `docs/REPLAN.md`. Vendor pages were egress-blocked from the sandbox; every price and rate limit that is not read from this repo is a secondary-source number and is marked unverified in the text. Nothing here is public copy.

## Summary

KaizenEdu's live turn is measured only at the model hop (674 ms p50 TTFT for gemini-3-flash-preview with thinking off, docs/SPIKE-latency.md); ASR, TTS and the device path have never been measured (the one 'row 1' run in docs/metrics failed on every turn with 'OpenAI TTS API error: Forbidden'). Reading the code, the current path cannot meet 1.5 s p50: 600 ms VAD lag + whole-utterance ASR + 4 DB round trips per media route + TTFT + buffered (non-streaming) TTS + decode is ~2.3-2.8 s before phone network. The model is not the bottleneck; the pipeline shape is. Cost per 15-minute session on the current path is about $0.27 (TTS ~44%, background gemini-3.5-flash hops ~22%, live LLM ~29%, ASR ~5%), reducible to ~$0.15 with prompt caching, a cheaper background model and shorter tutor turns; at 1k/10k/100k sessions a day that is roughly $8k/$81k/$810k a month today or $4.5k/$45k/$450k tuned. A realtime speech-to-speech path costs about the same on Gemini Live (~$0.23) and 1.5-2x on gpt-realtime-mini (~$0.35-0.45), and buys roughly a second of latency but forfeits model choice, the text prompt/eval stack and the whiteboard tag protocol. Two things must happen before anyone else uses the product: move the Gemini key to a paid tier (free tier is 5 RPM per model AND its terms allow Google to use inputs/outputs for training, which is untenable for a product used by 4-year-olds), and set TUTOR_PRICING_JSON in Vercel, because with the pricing table empty the ledger charges the 'unpriced' estimate (~164 cents per 15-minute session versus ~27 real) and a 25-minute teen session will hit the 300-cent ceiling and the daily cap will stop a guest after ~7 sessions. Abuse controls are real but cookie-scoped: a fresh guest is a fresh 120 minutes, the per-IP limit is in-memory per instance and only on guest creation, there is no Turnstile, and the global stop at $250/day will trip at ~1,000 sessions. Vercel now has native WebSockets in public beta (since 2026-06-22, Fluid required, connection pinned up to maxDuration 800 s on Pro), so the premise 'Vercel does not terminate WebSockets' is outdated, but a 25-minute session still does not fit; for a realtime model the choice is browser-direct with an ephemeral token (OpenAI /v1/realtime/client_secrets) or a small relay (Cloudflare Durable Object at well under $0.01 per session, or a Fly.io machine at ~$2/month). All external prices and rate limits below are from secondary sources (search summaries) and are marked unverified against the vendor page.

## Findings

### Latency: only the model hop has ever been measured; the code says the current pipeline cannot reach 1.5 s p50 regardless of model

Effort: S to measure (hours on a keyed laptop); M for streaming TTS + ASR (days); the region/JOIN fixes are S

Measured: gemini-3-flash-preview TTFT 674 ms p50 / 790 p90 with thinking off (8 samples, free-tier key, through this sandbox's proxy); reasoning-on is 2,099 ms; prompt size does not move TTFT (-71 ms across a 20x increase); the opening-sentence rule halves the first TTS payload (81 -> 30 chars). Never measured: asr, tts_first, first_audio, first_audio_pipelined, any device number. The only real 'row 1' harness run (2026-09-04, openai-tts + openai-whisper) errored on all six turns with 'OpenAI TTS API error: Forbidden', so its summary is all nulls. Reading the code, the serial floor is: VAD end-of-speech lag 600 ms (VAD_END_OF_SPEECH_LAG_MS) + whole-utterance ASR (client encodes WAV, POSTs multipart, server runs AI SDK transcribe on the whole clip; typical 300-600 ms for a 5-10 s clip, unverified) + 4 DB round trips in /api/tutor/asr (~140 ms at 30 ms RTT, measured) + 3 round trips inside startTurn (~75 ms) + 674 ms TTFT + ~100 ms to first sentence + 4 DB round trips in /api/tutor/tts (~140 ms) + non-streaming TTS (generateOpenAITTS does response.arrayBuffer(); tts-client.ts does the same; typical 300-500 ms for a 30-char sentence, unverified) + decodeAudioData. That is ~2.3-2.8 s p50 on the API side before a phone's network and audio start. Vercel cold starts and the absence of a pinned region (no `regions` in vercel.json; Neon region unknown) add an unknown amount. The realistic budget for this shape is ~2.5 s p50, which is exactly spec §12's go/no-go line. To get to ~1.0-1.3 s you need (a) streaming ASR with partials during speech so the transcript is final ~100-300 ms after end of speech (Deepgram Flux/Nova-3 streaming, OpenAI realtime transcription over WebSocket, ElevenLabs Scribe realtime), (b) streaming TTS bytes into the playback queue as they arrive (gpt-4o-mini-tts supports chunked transfer and SSE; the route already streams SSE, the TTS route and client buffer), (c) the JOIN in requirePrincipal the spike already names, and (d) a warm, region-pinned function next to the DB. Speech-to-speech (finding 8) removes ASR and TTS hops entirely and is the only way to ~0.6-0.9 s.

Recommendation: Before changing any provider, run `pnpm latency --product --turns 10 --assert-budget` on a keyed machine and commit the JSON; that single run answers most of the owner's question. Then, in order: stream TTS bytes (route returns the provider's body stream; client feeds MediaSource/decoded chunks), switch ASR to a streaming provider with partials, collapse requirePrincipal to one JOIN, pin the Vercel function region to the Neon region, and keep TUTOR_WARM_CONNECTION on once a handshake is timed. Only then decide on speech-to-speech.

### Abuse and fairness for an anonymous free product: what exists is per-cookie and per-instance; the identity is the cookie, so limits reset with 'Start over'

Effort: S for thresholds and Turnstile; M for the shared per-IP budget (new table + migration + tests); the counsel item is on the human list

What the code does today: (1) POST /api/tutor/guest mints a guest behind a token bucket keyed on the first x-forwarded-for address, 12 new identities per minute, in memory per Vercel instance, and only on creation; an existing cookie is re-levelled, not re-limited. (2) Priced routes call enforceRateLimits: soft per-principal token buckets per instance (turn 30/min, tts 120/min, asr 60/min, problem-extract 10/min) and a hard per-learner daily hop count from usage_ledger (llm 600, tts 2,400, asr 1,200, vision 60) that every instance shares. (3) Session start checks ai_kill_switch and the entitlement (GUEST.dailyMinutes 120 per UTC day per guest); ASR and TTS routes re-check the kill switch per hop; the turn engine holds a SessionBudget (300 cents) and DailyCap. (4) checkGlobalSpend sums usage_ledger once a minute per instance, writes a spend_alarm flag at $100/day and at $250/day flips ai_kill_switch on and posts to ALERT_WEBHOOK_URL; it is the global kill switch and it works. Gaps: the cookie is the only identity, so clearing it or pressing Start over (which deletes the rows) yields a fresh 120 minutes, and the only thing standing in the way is 12 new guests per minute per IP per instance, which under Fluid compute means 12 x (number of instances) and nothing per day; there is no Turnstile or any challenge (grep finds none); the daily hop and minute limits key on account/learner, never on IP; the global stop at $250/day equals ~1,000 sessions at $0.25, so the first real day of traffic turns the product off (GLOBAL_DAILY_SPEND_STOP_CENTS must be raised on purpose, and the alarm should page). On identifiers for minors: the 2025 COPPA amendments (effective 2025-06-23, compliance by 2026-04-22) keep the 'support for internal operations' exception under which an operator may collect a persistent identifier without consent solely for security/fraud prevention/site operation, but now require a notice naming those operations and the means used to prevent other uses; a third-party fingerprinting SDK, or Turnstile's own signals (IP, TLS fingerprint, and, per critics, WebGL), fall under that notice requirement and the Turnstile Privacy Addendum must be referenced in the privacy policy as a condition of invisible mode. Turnstile itself is free (unlimited challenges; widget count limit reported as 20 on the free plan by one source, unlimited by another). Cloudflare's anonymous-credential rate limiting (Privacy Pass-style, 'private rate limiting') is the privacy-preserving answer for exactly this problem but I could not verify it is available to ordinary customers today.

Recommendation: Layer, cheapest first: (1) raise GLOBAL_DAILY_SPEND_ALARM/STOP to the budget you actually intend and make ALERT_WEBHOOK_URL page a phone; (2) add a shared per-IP daily minute budget (a small table keyed on a salted hash of the address, or Vercel KV/Upstash) checked at guest creation and at session start, e.g. 3 guests and 240 minutes per address per day, with a friendly 'come back tomorrow' rather than a 429; (3) put Turnstile invisible on POST /api/tutor/guest only (free; the privacy policy gains the addendum reference and the COPPA internal-operations notice); (4) a Vercel WAF rate-limit rule on /api/tutor/guest and /api/tutor/turn at the edge (Pro plan; availability of custom rate-limit rules on your plan unverified); (5) do not add a commercial device-fingerprinting SDK for a product used by under-13s without counsel signing off the notice; hand counsel the exception text with the Turnstile question. ### Scale mechanics beyond price: vendor tier caps, per-instance limiters and DB round trips are what actually break at 10k-100k sessions a day

Effort: S to write down; the engineering is covered by the other findings

At 10k sessions/day the after-school peak is plausibly 1,500-2,500 concurrent sessions (US school hours compress traffic into ~4 hours); at 100k/day it is 15-25k concurrent. Per second at 100k/day peak that is roughly 60-100 live-turn requests, 60-100 ASR clips and 300-500 TTS sentences, i.e. 20-30k TTS requests per minute and ~$0.10-0.20 of Gemini spend per second, which is above Tier 1's $10 per 10 minutes by ~10x and above Tier 3's $200 by a little; OpenAI audio endpoints have their own RPM caps by usage tier (the exact TTS/transcribe RPM per tier is unverified). The in-memory token buckets and the 60-second spend-check cache are per instance, which is fine for protection but means the effective per-principal minute limit scales with instance count. Every media hop does 4 Postgres round trips and every turn 3, so a session is ~700 queries; at 100k/day that is ~70M queries, requiring a pooled connection string and the requirePrincipal JOIN. None of this needs solving for 1k/day; the pricing table (finding 5) and the paid tier (finding 9) are the two blockers at 1k/day.

Recommendation: Plan capacity in three steps with explicit gates: 1k/day on Gemini Tier 1 + OpenAI Tier 2-3 with the current architecture; 10k/day needs Gemini Tier 2-3, streamed TTS (fewer, longer TTS requests), the JOIN, a pooled DB, and a second live-turn provider as failover; 100k/day needs a Vertex or enterprise contract, a relay tier (finding 7) and a real cost dashboard from usage_ledger. Write the gate numbers into docs/PLAN.md so growth is a decision rather than an outage.
