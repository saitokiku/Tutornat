# Research: Realtime voice options (2026-09-30)

Produced by a research agent on 2026-09-30 for `docs/REPLAN.md`. Vendor pages were egress-blocked from the sandbox; every price and latency figure that is not measured in this repo is a secondary-source number and is marked unverified in the text. Nothing here is public copy.

## Summary

Bottom line: the fastest credible path to a sub-1.5 s tutor on THIS codebase is upgrade A (keep the text brain, stream both ends of the audio), and the single biggest lever is not a vendor swap at all but the 600 ms VAD hangover plus non-streaming TTS that the current loop pays on every turn. Nobody has ever measured the real first-audio number: docs/SPIKE-latency.md says so explicitly ("TTS and ASR are not" measured), and the only real measurement is Gemini 3 Flash TTFT 674 ms p50 with thinking off. Speech-to-speech (upgrade B) buys ~0.6-1.2 s time-to-first-audio on public leaderboards but breaks the tag grammar, the per-turn cost ceiling, the pre-model safety screen and (for Gemini) the hosting model, and it costs 3-10x more per session on OpenAI; it is worth a pilot only after A is measured, and only on OpenAI (or a to-be-verified Vertex path), because the Gemini API terms reportedly forbid services likely to be accessed by under-18s, which is the product's core audience and already applies to today's text loop. Two blockers precede any latency work: the Google key is on the free tier (5 RPM per model, DO-THIS-NEXT item 0) and no keyed `pnpm latency --product` run exists. Every vendor page (platform.openai.com, ai.google.dev, elevenlabs.io, deepgram.com, cartesia.ai, hume.ai, aws.amazon.com, artificialanalysis.ai) was egress-blocked from this sandbox; all external prices and latencies below are from secondary sources returned by search and are UNVERIFIED against primary text.

## Findings

### Today's loop, as coded, spends its budget before any provider is slow: 600 ms VAD hangover + whole-utterance ASR + 2 DB pre-flights + non-streaming per-sentence TTS + whole-clip decode

Effort: S (1 day, needs a keyed machine and a phone; no code)

The turn path is: VAD waits VAD_END_OF_SPEECH_LAG_MS = 600 ms of silence (lib/tutor/voice/vad.ts:71, redemptionMs at :310) before it calls the utterance done; the controller then encodes a WAV and POSTs the whole clip (turn-controller.ts submitVoiceAudio -> submitVoiceClip -> transcribeClip in asr-client.ts, one multipart upload); /api/tutor/asr runs a 4-way DB pre-flight then `transcribeAudio` (batch, no partials; asr-providers.ts:385-407 uses the AI SDK `openai.transcription`); the text goes to /api/tutor/turn whose engine does 3 more DB round trips (loadSession + replay lookup, then entitlement + two ledger sums) before `tutorStreamLLM`; the first `sentence` frame triggers /api/tutor/tts, which does another 4-way DB pre-flight and then `generateTTS` (buffered: the route builds `content-length` from `result.audio.byteLength`, tts/route.ts ~L195); the client then `decodeAudioData`s the whole clip (playback-queue.ts:331-347) before scheduling it. The controller subtracts the 600 ms back off `eosAt` so the reported figure includes the hangover (turn-controller.ts submitVoiceAudio comment). Measured pieces: Gemini 3 Flash TTFT 674 ms p50 / 790 p90 with thinking off, first sentence 774 ms p50 (SPIKE-latency, 2026-09-05 arms); DB depth 4+4+3 round trips (~190 ms + 75 ms at 30 ms RTT, SPIKE-latency 'Round-trip depth'). Unmeasured: asr, tts_first, first_audio_pipelined (SPIKE-latency 'What is still unmeasured'). Order-of-magnitude expectation for the real loop, UNVERIFIED: 600 (hangover) + ~150 (upload+preflight) + ~400-800 (batch mini-transcribe, secondary sources) + ~75 (turn preflight) + ~775 (first sentence) + ~400-700 (buffered gpt-4o-mini-tts of a 30-80 char sentence; secondary sources put first chunk at 300-500 ms even when streaming) + ~50 decode = roughly 2.4-3.2 s p50 from end of speech, i.e. likely over the 1.5 s p50 budget and near the 2.5 s spec §12 no-go line.

Recommendation: Before choosing any vendor: enable Google billing (DO-THIS-NEXT item 0), then run `pnpm latency --product --turns 10 --assert-budget` from a keyed machine and a 10-turn `?metrics=1` pass on a physical iPhone, and paste both tables into docs/SPIKE-latency.md. The decision between A and B is not makeable on the current evidence; the spike doc's own rule ('no number here is an estimate') should govern.

Evidence: lib/tutor/voice/vad.ts:71,310; lib/tutor/voice/turn-controller.ts (submitVoiceAudio, submitVoiceClip); lib/tutor/voice/asr-client.ts; app/(learner)/api/tutor/asr/route.ts (Promise.all pre-flight, transcribeAudio); lib/tutor/turn/engine.ts (startTurn Promise.all, runTurn Promise.all, tutorStreamLLM); app/(learner)/api/tutor/tts/route.ts (generateTTS, content-length header); lib/tutor/voice/playback-queue.ts:331-347 (decodeAudioData, createBufferSource); docs/SPIKE-latency.md (status line, 2026-09-05 arms table, round-trip depth table, 'What is still unmeasured'); kaizen.config.ts LATENCY (1,500/3,000 ms).

### OpenAI Realtime API (gpt-realtime-2 / 2.1 family): WebRTC + sideband WebSocket gives a browser-direct audio path with the server still in control; TTFA ~1.1-1.2 s on public benchmarks; ~$0.90-1.65 per 15 min with caching on the flagship, ~$0.30-0.75 on mini (all UNVERIFIED, primary page blocked)

Effort: L (2-4 weeks for a pilot; see phased path finding)

Transports: WebRTC for browsers, WebSocket for server-to-server, SIP for phones (secondary: forasoft, Microsoft Learn summaries). Browser auth: the server mints an ephemeral client secret (POST /v1/realtime/client_secrets; older docs say /v1/realtime/sessions) with `expires_in` that only bounds session START, not duration (github.com/openai/openai-realtime-agents/issues/119, fetched). Server-side control: the server POSTs the browser's SDP to /v1/realtime/calls with the real API key, gets a `Location` header with a call_id, and opens a sideband WebSocket `wss://api.openai.com/v1/realtime?call_id=...` to observe every event, receive transcripts, answer function calls and send `session.update`/`response.create` (developers.openai.com/api/docs/guides/voice-server-controls per search; a community thread dated 2026-09-09 reports 404 `call_id_not_found` on the sideband when the call was created with an ephemeral key rather than the API key, so create the call server-side). Native barge-in via server VAD or semantic VAD (`turn_detection`), with `conversation.item.input_audio_transcription.delta` streaming the learner's words (community + LocalAI docs per search). Function calling: 'function' tools only. Transcripts: output transcript is free; input transcription is opt-in via `input_audio_transcription` (gpt-4o-mini-transcribe) and billed separately (UNVERIFIED). Session limit: 60 min on OpenAI (was 30), 30 min on Azure (Microsoft Q&A + community per search). Latency: Artificial Analysis Big Bench Audio TTFA gpt-realtime-2.1 High 1.21 s (x.com/ArtificialAnlys per search); a blog reports gpt-realtime-2 at 1.12 s on minimal reasoning vs 2.33 s on high; OpenAI says p95 across the line dropped ~25% with 2.1 (July 2026, per search). One production case study: ~1.4 s -> ~600 ms first token after keeping the peer connection warm and moving the token endpoint near users (sheerbit per search). Pricing (secondary, tokenmix/hackernoon/forasoft summaries, July 2026): gpt-realtime-2 $32/1M audio in ($0.40 cached), $64/1M audio out; 1 token per 100 ms user audio and per 50 ms assistant audio -> ~$0.019/min heard, ~$0.077/min spoken; mini $10/$20 per 1M. Because every turn re-reads the whole conversation as input, measured all-in cost is $0.06-0.11/min with prompt caching and $0.18-0.46/min without (hackernoon '4,000 measured sessions' per search). 15-minute session estimate: flagship $0.90-1.65 (cached) up to $2.70-6.90 (uncached); mini $0.30-0.75. Compare kaizen.config COST.targetCentsPerSession 120 cents per 30 min and hardCeilingCentsPerSession 300.

Recommendation: If B is piloted, do it on OpenAI with the server-created call + sideband pattern (key never in the browser, transcripts and tool calls land on our server), on gpt-realtime-2.1-mini first, with prompt caching and a per-session `response.done` usage meter feeding usage_ledger. Note OpenAI's under-18 API guidance (below) before exposing it to the 4-8/9-12 bands.

Cheapest and fastest on paper, but it cannot run on the free tier, needs a long-lived relay host, and has no server-side sideband, so it is the wrong first pilot for this product.

Effort: S (1-2 days for the streaming provider; the A/B is one env var today)

### Upgrade A (keep the text loop; stream ASR and TTS): expected ~1.2-1.7 s p50 first audio (UNVERIFIED), ~$0.25-0.65 per 15-minute session, and nothing in the record, safety, ceilings or audio invariant has to change shape

Effort: A1: M (3-5 days). A2: M-L (1-2 weeks, new vendor key or OpenAI transcription session). A3: S.

Where the time goes after A: end-of-turn ~300 ms (Flux/semantic endpointing) or the existing 600 ms VAD hangover if ASR stays client-VAD-driven; final transcript ~100-300 ms after end of turn because partials were streamed during speech (Cartesia Ink 'time to final transcript 0.1 s' per search; Flux 'turn-complete transcripts'); turn pre-flight ~75 ms (SPIKE-latency); first sentence ~775 ms p50 (measured, Gemini 3 Flash, 30-char opening-sentence rule cuts TTS payload, SPIKE arms C/D); TTS first byte ~75-200 ms streaming (ElevenLabs Flash / gpt-4o-mini-tts pcm, secondary sources); no decode (raw PCM scheduled straight into AudioBufferSourceNodes) ~20 ms. Sum: ~1.25-1.6 s with an end-of-turn model, ~1.6-1.9 s keeping the 600 ms hangover — near or inside the 1,500 ms p50 budget, and the 3,000 ms p90 is plausible because the p90 tails on the measured LLM hop are ~120 ms wide except one free-tier outlier. Cost per 15 min (my arithmetic on secondary prices, ~30 turns, ~6 min learner speech, ~7.5 min tutor speech): ASR $0.02 (gpt-4o-mini-transcribe $0.003/min batch) to $0.07-0.12 (Deepgram streaming bills connection minutes); LLM $0.10-0.20 (30 turns x ~6k input tokens at $0.50-0.75/1M plus ~4.5k output at ~$4.50/1M; the ~15,800-char system prompt is a cost lever, SPIKE arm E, and Gemini context caching would cut it); TTS $0.11 (gpt-4o-mini-tts) to $0.34 (ElevenLabs Flash). Total ~$0.25-0.65, inside the 120-cent-per-30-min target. What breaks: (1) `sink.decode(bytes)` in playback-queue.ts assumes a whole decodable clip; streaming PCM needs a chunked path (scheduled `AudioBufferSourceNode`s at `context.currentTime`-aligned offsets or an AudioWorklet ring buffer) while keeping `stop({fadeMs:20})`, `pause`/`resume` for tentative VAD barge-in and the generation token; (2) `x-tutor-audio-ms` and `measureAudioDuration` disappear for streamed bodies (the header is optional already; `durationMs` may be null); (3) `content-length` goes away (route returns `Response(stream)`); (4) tts-client.ts `response.arrayBuffer()` becomes a `response.body` reader; (5) the TTS usage line is still charged by characters up front, so ceilings are unchanged; (6) for streaming ASR the `asr` usage line is by seconds and already trusts a client `durationMs`, so a browser-direct transcription socket (OpenAI ephemeral transcription session or Deepgram temp key) changes nothing about trust: the turn route already accepts client text (`inputMode: 'voice'`, engine.ts parseTurnRequest); (7) invariant (b): a browser-direct ASR socket means learner audio never touches our server at all, which is stronger than today; a server relay would put audio bytes in our process memory and must live under lib/tutor/voice/** so tests/invariants/no-audio-persistence.test.ts scans it; (8) the tag grammar, `sentence` frames, checks, hints, assisted/unassisted evidence and the pre-model `screenLearnerText` filter are untouched because the model still sees text and emits text; (9) `tutor:asr-result` mark semantics change (partials) — keep the mark on the final. Hosting: streaming TTS is a chunked HTTP response and works on Vercel Functions as-is (maxDuration 30 on the route); streaming ASR needs either a browser-direct vendor socket with an ephemeral token minted by a new route, or a WebSocket relay that Vercel's WS beta caps at 5 min (30 min Pro beta) — prefer browser-direct.

Recommendation: Do A. Phase A1 (first, biggest payoff per line): streaming TTS route + PCM playback + one env-var A/B between gpt-4o-mini-tts pcm and ElevenLabs Flash; measure. Phase A2: streaming ASR with an end-of-turn model, browser-direct via ephemeral token, and retire the 600 ms hangover on desktop/hands-free while keeping PTT on mobile. Phase A3: cost-only work — Gemini context caching of the static prompt prefix and the JOIN in requirePrincipal (SPIKE 'two of the four remaining round trips').

### Upgrade B (speech-to-speech with tool calls, server relay as record-keeper): ~0.6-1.2 s TTFA on leaderboards plus tool-call round trips for drawings, $0.30-1.65 per 15 min on OpenAI (mini/flagship, cached) or ~$0.20-0.35 on Gemini; it breaks the tag grammar, the per-turn ceiling check, the pre-model safety screen, the check/hint evidence flow, and the Vercel hosting model

Effort: L (2-4 weeks pilot + new host + new invariant tests); not a replacement, an option
