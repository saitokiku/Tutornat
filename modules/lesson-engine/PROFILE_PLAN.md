# Profile-first teaching — bounded integration plan

Astra execution instructions for separate Opus implementers and reviewers. Authority: `../DIRECTION.md`. This extends the existing lesson loop; it is not a new stack, an organizer revival or a child launch. Checkpoint target: 45 minutes from first implementer dispatch, including integration/reviews; at most two corrective rounds. Preserve and report anything unverified at that checkpoint. Do not reset the budget for a renamed phase.

## Shared contract

- Begin with a name/nickname (trimmed 1–40 characters) and integer age (1–120). Name is a local label, never identity/authentication. Use invented profiles in this adult-owner preview. One active profile is enough: no accounts, account database or multi-profile manager. Keep it in tab memory by default; remembering it and its learning record is an explicit browser-local opt-in. Editing name changes the local label; changing age/learner invalidates outstanding work and requires confirmation before discarding the active lesson. Never send the profile label in an API request or operational log. Age is self-reported personalization, not eligibility/consent or assessed ability.
- New generation request: `POST /api/lesson`, JSON `{adultTest:true, age:integer, goal:string<=300, locale:'en'|'es', previous?:{goal,reason}}`. No subject whitelist or grade selector. Goal itself supplies the topic. New lesson version 2: same id/title/goal/intro/three steps/path as v1, with `age:integer`, `subject:string<=80`, `locale`, no required grade. Validate new metadata matches requested age/locale. Preserve read/render support for v1 saved lessons; never silently migrate or delete old storage. Any retained legacy API accepts only its documented v1 shape and does not substitute an invented age.
- Existing numeric/choice/writing semantics remain. Writing is ungraded; local generated keys may be wrong. A next-step advance requires the latest fresh-check record to say `source:'local-check'`, `assisted:false`, `verdict:'correct'`. Everything else reinforces. This explicitly resolves the old S14 boundary while touching this contract; old raw tests/evidence remain intact.
- Existing visuals remain. Add one generic teaching representation: `sequence` with `caption<=200` and `stages` (2–6), each `{label<=60, detail<=240}`. It is a labeled process/timeline diagram, not a generated video. Animate the diagram and existing manipulatives with original CSS/SVG, no remote code/HTML/URLs/assets. Bounded demonstration → pause → learner turn; replay and manual next/previous remain available. Never auto-submit/auto-advance a lesson or count watching as understanding. Guided demonstrations that reveal a solution count as assistance; fresh checks do not auto-reveal. Reduced-motion keeps the complete equivalent interaction static.
- Two-way voice is explicit turn-taking, not always-listening: user starts/stops recording, reviews transcript, then submits; teacher text may be read aloud with browser speechSynthesis using a localService voice only. Typed path always works. Camera stays disabled. Microphone starts only after disclosure and a user gesture, clearly shows recording, stops all tracks on stop/cancel/navigation/profile change, and hard-stops at 20 seconds. No microphone activation during automated tests except a clearly synthetic device. Never play synthetic speech through speakers.
- Voice server contract: `POST /api/transcribe?locale=en|es`, raw audio body <=1 MiB, supported media type, `x-adult-test: true`. The existing server verifies same origin before dispatch. New `voice.mjs` exports `transcribeRequest(req, options={})`, resolving `{transcript,language,local:true}` or throwing a sanitized `{status,error,message}`. Local-only cached faster-whisper base CPU/int8, forced Hub-offline. Decode duration <=20 seconds, bounded subprocess/output, one local in-flight slot, typed no-speech/unsupported/too-large/unavailable/timeout failures. Audio temporary file mode0600 under `$TMPDIR`, deleted in success/failure/abort/timeout; no cloud fallback, transcript/audio logs or persistence. EN/ES language is per request, not inherited global English config. Node route returns standard security headers; `microphone=(self)`, `camera=()` remains.
- Dashboard is the owner's existing Kaizen interior, not a fresh aesthetic: `snapshots/Kaizen-AI/web/app/dashboard/page.js:600–711` and `redesign/candidate/styles.css`. Warm paper, neutral 240px rail, ink action buttons, restrained rose selection, existing native/system font stack. Lesson remains the main work surface. Rail destinations may expose actual Learn / Next step / Record views only; no dead navigation or invented metrics. On phones use compact real navigation and readable work. EN/ES preserved.
- Keep the verified private Activity panel and all asynchronous guards. It records observed operations, never model internals. Accurate disclosure: profile label stays local; learning goals, self-reported age and submitted text go to Anthropic; optional recorded audio is transcribed on this machine and discarded. Never say broadly 'nothing is uploaded'. Local speech capability is not natural-speech accuracy, nor validated teaching/safety for every subject.
- Fable writes the bounded teaching guidance: age-aware, all topics within safety limits, no copied entertainment IP, short explanations + purposeful repeated practice + learner turns, no manipulative retention. A safe out-of-scope response is `{refusal:string<=500}` handled as a typed non-success rather than fake lesson or generic broken-JSON error. High-risk personalized professional advice remains general education; disallowed operational harm refused. Feedback must include the exact learner-visible visual/passage, subject, age or legacy grade, locale and submitted answer as untrusted data. English-language-practice content may stay English while scaffolding is Spanish. Never include profile names.

## Non-goals and exit condition

No changes to originals, `snapshots/`, `redesign/candidate/`, old `frontend/`, `release/`, frozen source/tests/evidence, provider config, git, deployment, purchases, cloud accounts or real-family records. No camera, biometric attention/emotion inference, attention scores, streaks, autoplay feed, stock cartoon imitation, custom framework, new dependency or streaming infrastructure. This is a bounded local owner preview, not a compliance/efficacy/curriculum claim. A checked runnable preview and an honest unresolved list beat an unbounded repair loop.
