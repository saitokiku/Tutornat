`GET /api/health` -> `{ok:true, mode:'owner-test', model:'claude-fable-5-1'}`; do not treat this as proof of a live provider call.

`POST /api/lesson` request `{goal:string (1..300), subject:'math'|'english', grade:'K'|'1'..'8', locale:'en'|'es', adultTest:true, previous?:{goal:string,reason:string}}` -> `{lesson: Lesson, provenance:{provider,model,live:true}}`.

Lesson (schema v1): `{version:1,id,title,goal,subject,grade,locale,intro,steps:[Step,Step,Step],path:{reinforce:{goal,reason},advance:{goal,reason}}}`. Three distinct items: first two guided practice, third fresh check. Step: `{id,prompt,explanation,hint,kind:'choice'|'numeric'|'writing',choices?:string[],answer?:string,visual:Visual}`. Choice answer is exact option text; numeric answer is a numeric/fraction string; writing has no deterministic answer. Visual: `{kind:'fraction',parts:integer(2..12),filled:integer(0..parts),caption:string}` OR `{kind:'numberline',min:number,max:number,value:number,caption:string}` OR `{kind:'passage',text:string,caption:string}` OR `{kind:'tokens',count:integer(1..30),caption:string}`. Require meaningful subject-appropriate visuals and distinct check vs practice prompts. All strings bounded, numbers finite; no arbitrary HTML/JS/URLs. Grade/subject/locale must match request, not model overrides. Model refusal/invalid schema/missing content -> explicit error, no fake lesson. Labels/text and English/Spanish content must be coherent, not an empty translation claim.

`POST /api/feedback` request `{adultTest:true, lesson:Lesson, stepId:string, answer:string(0..1500), mode:'hint'|'answer', priorHints:integer(0..5)}` -> `{feedback:{text:string, verdict:'correct'|'incorrect'|'ungraded',nextAction:'retry'|'continue', alternateExplanation:string},provenance:{provider,model,live:true}}`. Feedback uses the actual response/context; on misunderstanding changes explanation, not repeats. Writing verdict is always ungraded in evidence/UI: AI feedback, not a validated assessment. Local choice/numeric correctness is canonical; a model cannot override it. On failed feedback request preserve answer and progress; show Retry, not fabricated success. Hint must not change a check into an unassisted pass. Parse failures are ungraded, never silently incorrect/50%.

Shared `core.mjs` exports `validateLesson(value)` (returns validated Lesson or throws), `gradeAnswer(step,answer)` -> `{verdict:'correct'|'incorrect'|'ungraded',reason:string}`, and `chooseNext(lesson,evidence)` -> `{goal,reason,kind:'reinforce'|'advance'}`. Evidence is `{lessonId,stepId,answer,verdict,assisted:boolean,source:'local-check'|'ai-feedback',at:string}`. UI supplies no-hint and hinted attempt records explicitly; unknown external assistance is not proved absent. chooseNext conservatively reinforces unless the fresh check is correct without requested help; writing-only evidence reinforces. These are suggestions, not mastery. Completion/time spent never become mastery; no percentages/durable-learning claims. UI creates immutable IDs/dates for evidence; no destructive replacement on async completion after new lesson/reset.

UI may use `fetch` directly. Browser opts into local persistence with an unchecked native checkbox; one versioned bounded JSON record with current lesson, answers/progress, evidence and proposed path. Catch unavailable/quota/corrupt storage and keep work in memory, disclose not-saved. Resume actually persisted work after reload. Clear saved work has explicit confirmation and generation invalidation, cannot be undone by late network response. Export current learning record as JSON; test actual downloaded bytes. No cross-device or account claims. Never translate/overwrite authored responses when locale changes; changing locale applies to the next generated lesson and preserves current work.
