## Five connected destinations

1. **Today:** parent sees actionable help flags, pending decisions and next academic actions derived from actual local records; student sees one actionable next task, current plan and visible support choices. Clicks navigate to the exact relevant record rather than another example. No decorative stats, fake mastery or marketing hero.
2. **Schoolwork:** a real list/filter/detail/edit flow. Create a fictional task with title, subject, due date and short instructions; validate inputs; edit without changing identity/evidence; archive with confirmation and undo. Empty state leads to Add task or load explicit sample. A sample teacher-note intake can propose an extracted task with clearly synthetic source and review/correction before confirmation; it must not claim arbitrary pasted text was parsed by AI. Created/edited tasks immediately reach Today, Workspace, Plan and Record where relevant.
3. **Workspace:** selected task context, shared visual/typed work, help controls, history and work state. Start, add an authored step/note, request available help, flag stuck, and mark complete (self-report) really update the selected task/session. For reviewed math/literacy samples, deterministic scaffold/checker behavior can be reused with honest scripted labels. For arbitrary user-created tasks, retain work and support organization but say live tutoring/checking is unavailable; NEVER produce fake correct-answer judgments or invent an AI response. Typed workflow is complete. Voice is an explicitly scripted text demonstration or unavailable control with typed recovery, not real audio. No unsupported arbitrary answer-solving.
4. **Plan:** shared schedule/list built from current task dates and unfinished records, plus proposed changes. Parent can request a mock draft, review, accept/decline; student in grades 6–8 can propose task/date/reason and see parent decision. Acceptance is explicit. Changes to ANY dependent task invalidate old plan/draft appropriately; another task's update cannot clear the warning. Re-draft/re-accept is reachable, and errors preserve previous accepted plan. Show true date provenance and historical decisions, not made-up confirmations.
5. **Record:** task-linked activity, authored contributions, requested/scripted assistance, parent observations and work status, with clear source labels. Parent can add a verbatim observation tied to a task; student sees an age-appropriate account of parent-visible information. Completion/observation/assisted correctness is NOT mastery. Independent checks can be shown only as planned/unavailable, not as actual assessment. The planned 48–72h/day-seven cadence is a product proposal, not a learning-effect claim.

## Cross-cutting acceptance criteria

AC-01 — **Custom task, not fixture theater.** Through actual controls create at least two different fictional tasks with different titles/dates; edit one and prove the same ID/date/text reaches the appropriate parent/student lists/workspace/plan. Archive/undo and no-task states function. Inputs safely escaped, trimmed/length-limited as documented; no eval or arbitrary code paths.

AC-02 — **Complete connected journey.** Parent creates/reviews task → student starts it and writes their own work → hint/help/progress recorded → parent reads exact work and adds attributed observation → accepted shared plan or proposal decision appears in both roles. Navigation and reload disclosure are meaningful. No core dead ends or ornamental controls.

AC-03 — **Actual local service boundary.** Domain store supports tasks, task-linked sessions/assistance, observations, proposals and plans, scoped to stable demo learner IDs. Service calls return a consistent result/error shape. Controls expose a secondary labeled scenario panel: normal, delayed/loading, fail-once/retry, unavailable/offline. These simulate services without calling a network. Success says local/demo when needed, never “sent to school” or “saved to your account.” Implement stateful behavior, not fabricated API transcripts.

AC-04 — **Races and draft safety.** Prevent double-submission duplicates; operations retain originating learner/task IDs; reset invalidates pending work; archive/edit invalidates conflicting pending plan results; late responses cannot resurrect deleted/reset data or overwrite newer edits. Role/locale/route changes do not discard authored form drafts or change provenance. Learner switch does not leak another learner's draft or apply pending changes to the newly selected learner. Preserve each learner's in-memory example, or explicitly confirm any destructive scenario reset. Cancel and retry have deterministic tested semantics.

AC-05 — **Age and language.** K–2: one short next action, large visual cues/targets, explicit adult scaffolding; do not claim independent non-reader usability without real audio/validation. Grades 3–5: short manageable plan and supported ownership. Grades 6–8: student proposals and explicit parent visibility. English/Spanish cover navigation, forms, errors, loading, empty states, ARIA/status and example copy. Authored messages/observations/titles stay verbatim across locale changes. Spanish remains draft educational copy requiring human review.

AC-06 — **UI quality.** Primary Operate surface with a task-centered Learn workspace; deliberate parent/child hierarchy. Local Avenir/humanist sans stack, restrained teal/warm-neutrals, useful spacing, no gradients/glass/fake metrics. Responsive navigation and deliberate 1440/768/390/320px layouts, no inaccessible overflow or sticky occlusion. Desktop and mobile screenshots must be inspected, not merely generated. Parent and student routes must each feel complete, not tab labels over one reused demo panel.

AC-07 — **Accessibility and feedback.** Semantic labels/buttons/landmarks, 44px minimum actionable targets, visible focus and meaningful successor after rerenders, forward/reverse Tab and Enter/Space, skip link, live feedback, keyboard-reachable cancel/retry/undo and disclosure. Essential contrast and reduced motion. Validate date/title errors at the form, not only a generic status region. Dialogs return focus. No claim of full assistive-tech certification.

AC-08 — **Honesty and technical boundary.** Persistent concise localized “frontend demo / synthetic data / memory only / AI and school connections simulated” disclosure; no auth masquerade; no real school integrations, tutoring marketplace or human tutor dependency. Restrictive no-network CSP, no remote fonts/assets, no fetch/WebSocket/beacon from the app, no storage APIs. Frontend works locally without backend. Arbitrary tasks are not represented as instructionally supported merely because organization works.

AC-09 — **Old invariants retained where applicable.** Date conflict checked at domain acceptance boundary, immutable assistance/source history, idempotent scripted replay, requested help counted separately, safe whole-number answer parsing on any supported sample (1225 must not match 225), all-dependency staleness, task-isolated sessions and locale preservation. Every reused invariant has a new-domain regression or an explicit reuse test. A declined draft cannot be accepted just by directly calling the domain function.

AC-10 — **Deliverable and evidence.** Runnable index.html, no dependencies, current README with exact opening/test commands, design-token/components note and FRONTEND_BACKEND_CONTRACT.md mapping mocks to real services and release gates. Tests must run and raw artifacts must exist. Report what works, what is deliberately simulated and what is missing; do not call the whole frontend finished if required journeys are incomplete.
